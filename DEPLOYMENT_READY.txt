PLAYER GAME FLOW:
1. Player joins game with their purchased ticket
2. Player sees ticket numbers in 3×9 grid
3. As admin announces numbers, they auto-mark if matched
4. Player claims wins (First Line, Two Lines, Full House)
5. System auto-detects if multiple players claimed same prize tier
6. Prize split announced automatically (TIE x2, TIE x3, etc.)

ADMIN GAME FLOW:
1. Admin creates new game
2. Waits for players to join
3. Clicks "START GAME" to begin auto-drawing
4. Numbers drawn automatically every 6.5 seconds
5. Numbers announced via voice + display
6. Pauses/Resumes game as needed
7. Monitors winners and tie detections
8. Can verify all player tickets in second tab

================================================================================
                        DATABASE SCHEMA
================================================================================

TABLE: tickets
├── id (INTEGER PRIMARY KEY) .................. Unique ticket ID
├── playerName (TEXT NOT NULL) ................ Player's name
├── ticket (TEXT NOT NULL) .................... 3×9 grid as JSON array
├── purchasedAt (DATETIME) .................... Purchase timestamp
└── used (BOOLEAN) ............................ Used flag (for future)

SAMPLE QUERY:
SELECT * FROM tickets WHERE playerName = 'kiso' ORDER BY purchasedAt DESC;

================================================================================
                        WEBSOCKET MESSAGES
================================================================================

CLIENT → SERVER:
- create_game: Admin creates new game
- join_game: Player joins with ticket
- announce_number: Admin announces number
- claim_win: Player claims win

SERVER → CLIENT:
- game_created: Game ID returned
- game_joined: Player joined confirmation
- number_announced: New number announced
- player_joined: New player notification
- player_count: Updated player list
- winner_announced: Win verification (with tie info)
